GraphRAG Needs Corpus Maps

Tech

Critical / Retrieval Architecture GraphRAG: How AI Answers Questions Hidden Across Many Documents

Pre-read: Enterprise agents only get useful when they can answer questions about a company's operational memory, not merely retrieve the page that resembles a prompt. Microsoft's GraphRAG global-search docs frame this as a split between local entity questions and global corpus questions, with global search leaning on precomputed community reports rather than plain vector neighbors. That distinction matters for robotics and infrastructure teams because incident reports, design docs, and launch reviews often encode patterns across many documents.

Summary: ByteByteGo gives a clear systems-level walk through of why standard RAG breaks on questions whose answer exists as a distribution across a corpus. The article separates local queries, where the answer resembles the question and lives in a small text region, from global queries, where the system must survey a whole collection. It then explains GraphRAG's indexing pipeline: chunk documents, extract entities and relationships, merge duplicate descriptions, optionally extract claims, cluster the graph into communities, and generate community reports before query time. Local search starts from matched entities and expands through text units, neighbors, relationships, claims, and community reports, which matches Microsoft's local-search description. Global search uses community reports in a map-reduce flow, which Microsoft describes in its GraphRAG docs. The practical warning is cost: full GraphRAG spends heavily at indexing time, while Microsoft's LazyGraphRAG research note claims vector-RAG-level indexing cost, 0.1 percent of full GraphRAG indexing cost, and much cheaper global queries. The useful takeaway is architectural rather than vendor-specific: retrieval quality depends on matching the query type to the memory structure, and routing mistakes become a new failure mode for agent systems.

Ideation

Ideation

Idea 1 Memory Regression Tests for Agents

Sell a test harness that tells enterprises when an agent is about to act on stale, contradictory, or under-supported internal context. The primitive is not a better company search box. It is a CI system for operational memory: before a support, finance, legal, or engineering agent changes a ticket, sends a customer answer, approves a workflow, or opens a PR, the harness asks corpus-wide questions against the company's documents, incidents, policies, owners, and past decisions and blocks actions when the answer depends on broken memory.

Why Now

Companies are moving from chatbots to agents that change systems. At the same time, internal knowledge is becoming more fragmented: Slack, Linear, docs, postmortems, CRM notes, policies, runbooks, and code comments all disagree. Bigger context windows do not solve the global question: is this instruction still true across the whole organization?

First Wedge

Start with engineering incident and support escalations. Connect to Linear/Jira, Slack, GitHub, docs, and postmortems; generate a daily memory test suite around ownership, customer commitments, known failure modes, and policy exceptions; then gate agent-written support replies or runbook actions when the graph finds conflicts or weak evidence.

Commercial Model

Heads of support, engineering productivity, or AI platform pay because one bad agent action can create churn, compliance exposure, or an outage. Price by connected knowledge surface plus checked agent actions, with an enterprise plan for regulated audit logs and approval workflows.

Defensibility

The asset is the customer's evolving map of claims, owners, exceptions, reversals, and action outcomes, not a generic GraphRAG stack. Every blocked action and human override teaches which contradictions matter. Incumbents can add retrieval, but they do not naturally own the cross-system regression history tied to agent decisions.

Technical Risk

The hard part is separating real contradictions from normal organizational mess. The system needs temporal claim extraction, source authority ranking, and action-specific thresholds, or it will either block everything useful or miss the dangerous stale-context cases.

Market Expansion

After support and incident work, the same shape applies to sales promises versus contract language, clinical operations SOPs, financial controls, security exceptions, vendor risk, and any workflow where agents act from a living body of internal rules.

Self-Critique

This could collapse into another AI observability dashboard or enterprise search product if it does not own an action gate. Buyers may also resist a blocker in fast workflows, so the first deployment has to run in shadow mode and prove it catches expensive misses without flooding teams.

Next Experiment

In two weeks, ingest one company's last 100 incidents, current runbooks, and support macros. Create 30 memory regression tests, run them against proposed agent replies or runbook steps, and measure how many blocks a senior engineer agrees would have prevented a stale or wrong action.
