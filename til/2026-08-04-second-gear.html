Critical / AI infrastructure Why An LLM's Memory Gets Expensive and How to Fix It

Pre-read: Long-context agents turn memory into an infrastructure bill because inference has to preserve working state while many requests share the same accelerator. Serving systems such as vLLM's PagedAttention improved memory packing, and API-level prompt caching made repeated prefixes cheaper, but both expose how central the cache has become. This piece is worth opening because it connects the math, the hardware bottleneck, and the serving tricks in one frame.

Summary: ByteByteGo explains that a transformer's KV cache stores key and value vectors for every prior token, layer, KV head, head dimension, numeric precision, and active request. A 70B model with a 128,000-token context can need roughly 40 GB of KV cache for one request, before batching multiplies the footprint. The key bottleneck is decoding: every generated token reads the retained cache from GPU memory, so long-context generation becomes memory-bandwidth-bound even when the model fits on the card.

The article walks through the main levers. Grouped-query attention and multi-head latent attention reduce what each token stores. Quantization cuts bytes per value, with 8-bit usually much safer than 4-bit for demanding retrieval. Eviction saves memory by dropping tokens, but it can erase the fact a future token needs. Paged attention attacks fragmentation, while prefix and prompt caching reuse shared blocks. The practical lesson is that agent systems with repeated long prompts should optimize for reuse, while long-document retrieval should be cautious about cache eviction.

Critical / AI buildout PoweredByWho Project Map

Pre-read: AI infrastructure is shifting from model-lab capex headlines into grid interconnection, water, permitting, and local politics. The strongest signal now is often the gap between announced capacity and projects that can actually be energized. A public map is useful because it lets you inspect the buildout as a permission system, not a press-release race.

Summary: PoweredByWho tracks public-record reporting on U.S. data centers and related political activity, with project status, permits, local opposition, and power scale exposed through a national map. When checked, the map listed 2,113 data centers across 46 states and 56.9 GW of announced capacity, while noting that its database is not comprehensive. The same page surfaces large pending projects, contested sites, high-water-use layers, and Q1 permit counts.

The useful part is not a single number. It is the taxonomy: built, construction, permit, announced, proposed, and contested are different realities. That distinction matters for GPU supply, power procurement, utility planning, and local backlash. Hardware FYI paired the map with Ed Zitron's capacity-skeptical essay, which is lower-certainty analysis but a useful warning against treating headline gigawatts as deployable compute.

Idea 1 Cache Boundary Auditor

Sell security and platform teams a test harness that proves where an AI provider or self-hosted inference stack reuses prompt and KV-cache state. The new primitive is cache state as regulated data-in-use: not logs, not stored files, but transient tensors that can still leak enough about a customer, tenant, region, or workflow to matter.

Source Signals

  • Why An LLM's Memory Gets Expensive and How to Fix It via ByteByteGo
    Long-context serving pushes teams toward prompt caching, paged attention, and KV reuse because decoding repeatedly reads the cache.
  • Prompt Leakage via KV-Cache Sharing in Multi-Tenant LLM Serving via NDSS 2025
    PROMPTPEEK shows that multi-tenant KV sharing can create side channels that reconstruct prompts.
  • Selective KV-Cache Sharing to Mitigate Timing Side-Channels in LLM Inference via arXiv
    Follow-on mitigation work treats cache sharing between untrusted users as a real privacy problem, not only a theoretical footnote.
  • LLM Caching via Helicone docs
    The visible commercial category is mostly cost and response caching, leaving provider-level cache isolation audit as a sharper wedge.

Why Now

Long-context agents make cache economics unavoidable, and provider prompt caching turns a backend optimization into a procurement and compliance question. Security teams already ask where data is stored and logged; they do not yet have a standard way to test whether cached inference state crosses tenant, region, model, or policy boundaries.

First Wedge

A paid audit runner for regulated AI platform teams: deploy synthetic canary prompts through OpenAI, Anthropic, self-hosted vLLM/SGLang, and internal gateways, then report cache-hit observability, isolation failures, residency ambiguity, and recommended cache policies.

Commercial Model

Security, AI platform, or governance teams pay $25k-$100k per annual environment for continuous cache-boundary tests and vendor evidence packs. The budget exists because a failed customer-data review can block model rollout even when the underlying model is approved.

Defensibility

The company compounds a corpus of provider behaviors, timing baselines, attack probes, contract language, and mitigations across real enterprise stacks. Incumbent observability tools can show spend and traces, but proving a negative about hidden provider cache reuse requires adversarial measurement, policy mapping, and buyer-trusted reports.

Technical Risk

The hard part is separating true cache side-channel signals from noisy provider latency and scheduling variance without internal telemetry. The product has to produce statistically defensible evidence, not scary charts from small samples.

Market Expansion

Start with prompt/KV-cache boundaries, then expand into data-in-use controls for agent sandboxes, vector indexes, browser sessions, tool-call caches, and confidential-computing attestations.

Self-Critique

This could be too early if major providers quickly publish strong cache-isolation guarantees and enterprise customers accept them without independent testing. It also fails if timing-based black-box tests are too noisy to survive a security review.

Next Experiment

In 2-4 weeks, build a black-box probe against vLLM/SGLang and two hosted APIs using repeated canary prefixes. Take the findings to five AI security leads and ask whether the evidence would help unblock an internal model-risk review.

Idea 2 Delivered Megawatt Ledger

Sell AI labs, utilities, energy suppliers, and infrastructure investors a probability-adjusted ledger of usable data-center capacity, not announced capacity. The primitive is delivered megawatts: a staged claim that moves from press release to permits, interconnection, power equipment, local consent, construction, energization, and finally revenue-generating compute.

Source Signals

  • PoweredByWho Project Map via Hardware FYI / PoweredByWho
    Public-record trackers already show the scale and geography of announced AI data-center projects, including permits, status, and contested sites.
  • Where Are All The Data Centers? via Hardware FYI / Ed Zitron
    The useful question is not how many gigawatts were announced, but how much capacity is actually energized and usable.
  • $64 billion of data center projects have been blocked or delayed amid local opposition via Data Center Watch
    Local opposition and permitting risk are now material enough to delay large projects across political lines.
  • Base Power raises $1B to roll out its giant new home battery via TLDR follow-up verification
    Grid flexibility is attracting billion-dollar financing because peak demand and data-center load are reshaping electricity planning.

Why Now

AI capacity planning is moving from chips to power, permits, water, transformers, and local politics. Buyers who sign compute, power, or equipment contracts need to know whether a site is likely to deliver usable megawatts on a specific date, not whether a developer announced an impressive number.

First Wedge

A data product for suppliers and energy buyers that scores 200MW+ U.S. projects by delivery probability and month-by-month slippage risk using permits, interconnection queues, utility filings, local meeting minutes, equipment lead times, satellite/construction signals, and opposition activity.

Commercial Model

Sell annual seats and API access to power traders, utilities, equipment vendors, hyperscaler procurement teams, insurers, and infra funds. Pricing can start at $30k-$150k per year because one wrong capacity assumption can misprice equipment, power, land, or compute commitments by millions.

Defensibility

The moat is not a map; maps are already becoming common. The moat is a verified event graph that learns which early signals actually predict energization, plus relationships with local permit watchers, utility dockets, EPCs, transformer suppliers, and community groups.

Technical Risk

The hard part is entity resolution and causal scoring across messy public records: proposed sites change names, developers hide behind LLCs, MW numbers mutate, and energization is often not directly disclosed.

Market Expansion

After AI data centers, the same ledger can cover battery fleets, hydrogen facilities, nuclear microreactors, transmission upgrades, factories, and other projects where announced capacity routinely diverges from operational capacity.

Self-Critique

This is crowded adjacent to construction intelligence, permit databases, and data-center trackers. It only clears the bar if the wedge is delivery-risk underwriting with timestamped confidence, not another searchable database of projects.

Next Experiment

Pick Texas and Illinois, score 30 announced data-center projects from public records, and backtest against known delays or utility filings. Then sell three pilot reports to a transformer supplier, a power trader, and a compute buyer.
